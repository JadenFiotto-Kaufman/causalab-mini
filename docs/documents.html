Documents

The document format field by field, with the JSON Schema.

A document is one JSON object and nothing else. It names a model, which column of a row each prompt comes from, the places inside the model to read and to write, the experiment those make up, and the steps that run it over rows. Nothing in it is code, and nothing in it is resolved: pos stays -1 and "weekdays/train" stays a string until the compiler resolves them against a loaded tokenizer and the rows on disk.

Two formats parse. The plan-shaped one below is the format — the one every document in documents/v2/ and documents/real/ is written in, and the one the schema verb describes. The other is a narrow reader for the protocol's own JSON, kept for the documents at the top of documents/. A document is told apart by shape: it is plan-shaped if it has steps.

At a glance

The smallest real experiment in the repository: read the residual stream at the last token of a counterfactual prompt, swap it into the same place on the base prompt, score what the model then says.

$ uv run causalab-mini validate documents/v2/patching.json
ok: documents/v2/patching.json is a valid plan-shaped document

Every object in the document is a pydantic model with extra="forbid", so a misspelling anywhere is a load error that names the path to it — interventions.patching.reads.v_cf.position — rather than a key that is quietly ignored and still changes the digest.

model

fieldtypedefaultwhat it is
keystringrequiredthe HuggingFace repository id
revisionstringrequireda commit, a branch or a tag. Part of the identity of the experiment, not a convenience
dtype"fp32" | "bf16"requiredwhat the weights are loaded as
attn_implementation"eager" | "sdpa" | nullnullabsent, the library's default. eager is the only one under which attention_scores and attention_probs exist

attn_implementation is part of the experiment rather than of the run: the implementations differ in the last bits, and a document that reads an attention pattern has to ask for eager. There is no device field. Where the weights sit is a property of the run, and is a flag — see what is not a document field.

roles, and the rows a step runs over

A role is one side of a paired prompt. Its only field is field, the column of a row its text comes from. Which rows it reads is not here: that is a step's, because two steps may run the same experiment over different splits.

A field is a path into the row: input is a column, counterfactual_inputs[0] one entry of a list-valued column, and a.b walks into a dict. The value has to be a string.

A step names its rows as a dataset ref: a path relative to the data root (--data-root, default documents/data), with an optional #split. A table is a JSON array of flat row objects and a split is a column of that table selected by value, not a second file — so weekdays/data#train is the rows of documents/data/weekdays/data.json whose split is "train".

$ uv run causalab-mini data weekdays/data
weekdays/data: 4 rows
  columns: answer, base_answer, cf_answer, counterfactual_inputs, counterfactual_inputs_variables, entity, input, label, split
  splits:  test, train
  sample:  {"answer": " Friday", "base_answer": " Friday", "cf_answer": " Saturday", "counterfactual_inputs": ["If today is Friday, tomorrow is"], "counterfactual_inputs_variables": [{"entity": "Friday"}], "entity": "Thursday", "input": "If today is Thursday, tomorrow is", "label": " Saturday", "split": "train"}

<column>_variables

A position may anchor to a variable — "this row's entity" — and each role then resolves its own text for it. The rule is the protocol's: the <column>_variables sibling of the role's own field first, then a top-level column of that name. For a role whose field is counterfactual_inputs[0], the variable entity is looked for at counterfactual_inputs_variables[0].entity, then at the column entity. That is what lets one position spec mean the right thing in both prompts of a pair. A name that is neither is refused on the client, naming both places it looked.

The forms a position can take are their own page; what matters here is that the anchor is a fact about the row, and so is resolved before anything runs.

sites

fieldtypedefaultwhat it is
componentstringrequiredone of the 21 names vocab lists
layers[int] | nullnulla one-element band. A layerless component takes none
heads[int] | nullnullat a per-head tensor, the heads this site is
units[int] | nullnullanywhere with a known width, the single features this site is

A site names heads or units, never both: they slice the same axis at two grains, and the site's width becomes theirs — len(heads) · head_dim, or len(units) — so a featurizer, a swap or a harvest there is of those and leaves the rest alone. layers is a one-element list; a band spanning several layers is one address and is not implemented. Which components exist, which are per-head, which are read-only and which need eager attention is the locations page.

featurizers

fieldtypedefaultwhat it is
kindsubspace | pca | gate | sae | linearrequiredwhat the parameter set is
kint > 0 | nullnullthe rank of a basis. A gate has none: its features are the units
parametrization"cayley""cayley"how a rotation is parametrized
seedint | nullnullthe draw the initial basis comes from. Absent, the fit's seed, or 0
file_pathstring | nullnullload the parameter from a safetensors bundle instead of drawing it

The validator pairs the kind with its numbers. A subspace or a pca needs k; a gate takes neither k nor seed, because it masks every unit of its site and starts at θ = 0. pca, sae and linear exist only as a file — nothing draws or trains one — so each needs file_path. A loaded featurizer has no seed: its weights are its bytes.

a loaded bundle is checked against the document

A rotation is a grid of numbers and nothing in the numbers says which model or which layer it came from. The safetensors header does. A bundle this project wrote carries a stamp — model key, revision, dtype, component, layer, kind, k, d, parametrization — and the load compares every key that is present against what this document declares, refusing by name on a mismatch. A bundle from elsewhere, a published SAE, has no stamp of ours, and then the shapes are all there is to check: its width must be this site's.

A featurizer does not say where it is. One name is one parameter set, so the site it acts at is derived from the reads and writes that name it — and a name used at two sites is refused, because one rotation cannot have two widths. The kinds themselves, and what each does to a read or a write, are on the ops page.

interventions

An intervention is the experiment, declared once. A step names the one it runs; when the document declares exactly one, it need not. That is why a fit and the run that scores it cannot drift apart — they are the same declaration over different rows.

fieldtypedefaultwhat it is
reads{name: object}requiredwhat comes out
writes{name: object}{}what goes in
models{name: object}{}an intervened model: a role, and the writes in force on it
metrics{name: object}{}what to score
decodeint ≥ 00tokens to generate after the prompt. 0 is one forward pass

reads

fieldtypedefaultwhat it is
sitestringrequireda declared site
pospositionrequiredwhere in the sequence. A bare integer is {"index": i}
inputstringrequireda declared role: whose prompt this forward runs
modelstring"original""original", or an intervened model of this intervention
featurizerstring"identity"read the activation in that parameter set's space

view: "logits" is only for the residual stream — embeddings, block_input, block_output, ln_final — because that is what the final norm and head expect, and it cannot be combined with a featurizer. A layer sweep plus a token_prob metric on a logits view is the logit lens, as one document.

writes

fieldtypedefaultwhat it is
sitestringrequireda declared site, not read-only

mechanismenumrequiredone of the six below

mechanism and operand are two fields

The protocol writes a mechanism as a key — {"swap": "v_cf"} — and a key that is itself the mechanism's name cannot be enumerated by a schema. The schema is what an agent reads, so here the mechanism is a value.

mechanismoperandrequired paramsoptional params
swapyes——
add_scaledyes—scale
lerpyest—
gaussiannoseedscale
clampnoat least one of lo, hi—
renormalizeno——

The validator checks the pair: a mechanism that takes no operand is refused one, a mechanism that needs an operand is refused without one, and params is checked by name both ways — missing and extra. gaussian draws its own noise, clamp only bounds, and renormalize measures against the pre-write value the seam supplies, so none of the three takes an operand.

An operand is one of four things:

spellingwhat it is
"v_cf"a read of this intervention
{"ref": "mean"}a value an earlier sibling step published under outputs
0.0a literal number — zero ablation
nullnothing, for a mechanism that takes none

The order of writes inside an intervened model is the order they apply. A renormalize restores the norm the other writes at its site changed, so it is refused unless it comes after at least one of them and last among them; first, or alone, it is the identity. What each mechanism does to the tensor is the ops page.

models

An intervened model has two fields: input, a declared role, and writes, the names of the writes in force on it. It is how one document holds two models at once — the steered one and the same one without the renormalize, say — and a read names which of them it reads.

A read in one model may be the operand of a write in another, so the forwards are ordered by that dependency. The graph has to be acyclic; it is the schedule, and a cycle is refused by the compiler.

metrics

Every metric has kind, of (the name of a read) and token_form, which is "space_prefixed" and is the only form. The rest of its fields name columns of the base rows, not literal strings: the answer is per row, so the document names a column and the table carries the text.

kindits columnsunitestimand
matchexpectedfractionmatch/v1
logit_diffa, blogitlogit_diff/v1
cross_entropytargetnatcross_entropy/v1
token_logittokenlogittoken_logit/v1
token_probtokenprobabilitytoken_prob/v1

of has to be a read of the same intervention, and that read has to be one position wide: a metric scores one position per row, so a window of several is refused with the width it found.

rows, and eligibility

A row whose value in a named column is null or empty is an excluded measurement — not a zero. Which rows a metric can be computed for is decided on the client, where the data is: the eligible rows are the ones where every column the kind names has a value, and that vector is compiled into the plan and written into the saved table. A column that no row has is a misspelling and is refused.

A metric none of the rows is eligible for is refused before anything runs: "a metric of nothing has no mean". An excluded row still appears in the output table, with value: null, eligible: false and a reason, so it can never shorten a denominator quietly.

{
  "example_id": "0",
  "metric": "logit_diff",
  "value": -0.02835773676633835,
  "eligible": true,
  "positions": null,
  "reason": "",
  "unit": "logit",
  "estimand_version": "logit_diff/v1",
  "produced_by": "a53cd70e47fa3a3f34c71dda53b00d72d528eba4495aae0dd2182719820acad9"
}

example_id is the row's example_id column if the table has one, and the zero-based row index otherwise.

decode: generating after the prompt

decode on an intervention generates that many tokens after the prompt, greedily, on every forward of it. With it, a position may name the continuation frame — {"frame": "generated", "index": k} — and the intervention publishes <model>.generated, the generated ids, which a save may take to a .safetensors file.

the decode is a bound, not a stopping condition

The generation runs with min_new_tokens equal to max_new_tokens and no sampling: EOS is held off, so the loop runs to its bound and the batch stays rectangular. How far a row meant to generate is then a result rather than a ragged tensor — its continuation frame is cut at its first stop token, and a row that never stopped has no eos segment, which comes home as a reported reason.

A generated position without decode > 0 is refused, as is a step beyond the bound. A write in the continuation frame is narrower still: it has to name a step the decode has already reached — {"index": k} with k ≥ 0, or {"all": true} — and takes no scope, because every other cut of the continuation is only known once the decode has finished.

steps

The steps run in the order written, and that order is checked. Three kinds, told apart by kind.

kindwhat it doesits fields
observeone pass over its rowsrows, intervention, outputs, saves
fittrains featurizers, then scores held-out rowsrows, intervention, params, objective, anneal, epochs, pairs, seed, optimizer, early_stop, eval, saves
weightspublishes fitted parametersnames, saves

An observe or a fit gives rows as role → dataset ref, and every declared role needs one. intervention is optional when the document declares exactly one.

saves

A save is {"value": …, "file_path": …} and it sits on the step whose result it names. value has to be something that step produces — a metric of its intervention, one of its outputs, a <model>.generated, or a name a weights step publishes — and naming anything else is refused with the list of what it does produce.

A metric goes to a JSON table; an output or a generated-ids value is a tensor and needs a .safetensors path. The path is relative to --out — or, in a swept document, to the point's own directory, which is the only nesting the output tree has. Every step of one document writes into that same directory.

the field is saves, not save

nnsight mounts a .save() method onto object, so every pydantic model in a process that has imported nnsight inherits one, and a field called save would shadow it.

outputs, and ref across steps

An observe step may publish values for the steps after it. An output has read (a read of its intervention), reduce and k:

reducewhat is publishedk
none (default)the read as it is, rows × widthnot allowed
meanone vector, averaged over rowsnot allowed
pcathe top-k principal directions, a basis a later document loads as a pca featurizerrequired

A bare string is shorthand for keeping the read unreduced: "outputs": {"active": "latents"} means {"read": "latents", "reduce": "none"}.

Mean ablation is the whole pattern in one document: one step harvests and publishes a mean, a later step swaps it in with {"ref": "mean"}. The mean never touches disk unless a save asks for it.

$ uv run causalab-mini explain documents/v2/mean_ablation.json
<root>: Plan
  harvest: Observe  metrics=[]  outputs=['mean=mean(acts)']  saves=['mean.safetensors']
      forward 'original' on 'base'  (4 rows x 11 tokens)
        read  'acts' at block_output[0] pos={index:-1} via 'identity'
  clean: Observe  metrics=['logit_diff/logit_diff']  saves=['clean.json']
      forward 'original' on 'base'  (4 rows x 11 tokens)
        read  'logits' at lm_head pos={index:-1} via 'identity'
  ablated: Observe  metrics=['logit_diff/logit_diff']  saves=['ablated.json']
      forward 'ablated' on 'base'  (4 rows x 11 tokens)
        write 'ablate' at block_output[0] pos={index:-1} swap(mean) via 'identity'
        read  'logits' at lm_head pos={index:-1} via 'identity'

Three things are checked about a reference. It must name an output an earlier step published — the message lists what has been published so far. Two steps may not publish the same name. And an output may not share its name with a read, because an operand names one or the other.

The compiler then checks the shapes, because it knows them and the block would only find out from a shape error: an unreduced output has to have the same row count and the same window as the write that swaps it in; a mean over a ragged read is one vector and broadcasts anywhere; and a pca basis is refused as an operand outright — a basis is loaded as a featurizer, not written at a site.

fit

fieldtypedefaultwhat it is
rows{role: ref}requiredthe rows it fits on
params[string]requiredthe featurizers it trains
objective[[number, string]]requiredΣ wᵢ·termᵢ, minimized
epochsint > 0requiredpasses over the rows
pairsint > 0requiredrows per update
seedint0the shuffle, and the initial draw of a featurizer with no seed of its own
optimizerobjectrequiredname ("adamw"), lr, weight_decay (default 0.0)
early_stopobjectrequiredmetric, mode ("max" | "min", default "max"), patience > 0
evalobjectrequiredthe held-out pass: its own rows, and its own saves
anneal{gate: object}{}a gate's temperature: start, end, geometric between
interventionstring | nullnullwhich experiment it fits
saves[object][]its own results: train/loss, train/eval

An objective term is a metric of the intervention, or <gate>.mask for a gate this fit trains — the mean of its soft mask, which is its L1 penalty. early_stop.metric has to be a metric. params has to be declared featurizers, and none of them may be a pca, sae or linear, which are fixed by definition. anneal may only name a gate this fit trains. The eval pass needs rows for every role, and its saves have to be things that pass produces.

If the fit's rows and the eval's rows are different refs, the compiler checks they are endpoint-disjoint and refuses with the number of shared rows. The same ref for both is the visible train-equals-test ablation, and is allowed.

a featurizer may not be used before it is trained

A step that runs a forward uses every featurizer its intervention names. If a later fit trains one of them, that earlier step scored an untrained rotation — a valid document with a silently wrong number. It is refused, with the fix in the message: move the step after the fit, or, for a deliberate untrained baseline, declare a second featurizer that no fit names.

weights

A weights step has names — declared featurizers — and saves. It is what writes a fitted parameter to a safetensors bundle, stamped with the identity a later document's load is checked against. An sae or a linear may not be named: its tensors are the file it came from, and there is no fitted weight to publish.

sweep

{"sweep": [a, b, c]} at any field means the document is three points: the same experiment three times, differing in that one field. A sweep is lowered on the client before anything is compiled, so a point is an ordinary document in every way — its own addresses, its own tokenization, its own digest — and nothing downstream knows a sweep happened.

spellingwhat it is
{"sweep": [0, 1, 2]}the literal values
{"sweep": {"range": [0, 16]}}0, 1, … 15. [start, stop] or [start, stop, step], as Python's
{"sweep": [-4, -1], "as": "pos"}a named axis: every wrapper with the same as moves together

Several swept fields are their cross product, one point per combination. The named axis exists because a cross product is sometimes the wrong thing: a patch reads at a position and writes at the same one, and swept separately those are N² points, most of them reading one place and writing another. Naming the axis makes them one coordinate.

Sixteen layers × two positions, and because pos is one named axis rather than two fields, that is 32 points and not the 64 a cross product would give. Each point is a directory named for the values it took — layers=12,pos=-1/ — in the order the fields appear in the document.

        forward 'original' on 'base'  (4 rows x 11 tokens)

Two places may not be swept: model and header. The engine loads the model once and every point runs against it, and those two are the identity of the run rather than a coordinate in it. Everything else the protocol allows here — at_once, cohorts, swept bundles — is refused by name.

header, and the digest

header has one field, description, and it is free text. Every document in the corpus uses it to say what the experiment is for and what its numbers do and do not mean; it is the first thing worth reading about a document.

The digest is the identity of the experiment: the SHA-256 of the document with header removed, serialized with sorted keys and no whitespace. It is what every metric row is produced_by and what a saved featurizer is stamped with. Rewriting the description does not make a new experiment:

$ uv run python -c '
import json
from causalab_mini.plan.spec import Spec
raw = json.load(open("documents/v2/patching.json"))
a = Spec.model_validate(raw).digest
raw["header"]["description"] = "anything else at all"
b = Spec.model_validate(raw).digest
print(a); print(b); print("same:", a == b)'
ffd162b5011bc74abf2f400d71595f63849a393a1fcf78aa234d26bbc77e791e
ffd162b5011bc74abf2f400d71595f63849a393a1fcf78aa234d26bbc77e791e
same: True

The converse is the reason nothing is quietly ignored: a key the reader skipped would still be in the bytes the digest is taken over, so two runs that did the same thing would claim to be different experiments — or worse, a key that changes the experiment would load, do nothing, and be stamped as if it had.

where a refusal lives

A check about one value is a validator on the node that holds it. A check about two pieces of the document — a read's site, a save's value, the order of the steps — is a cross-check on the whole Spec. A check that needs the loaded model — a layer number, a site's width, a row count, an attention mask's layout — is the compiler's, and raises PlanError. That is why validate is fast and offline, and why explain is the next thing to run.

The protocol format

The other reader accepts the protocol's own JSON, and only the subset of protocol_version 3 that this project runs. Every other real protocol feature is refused by name at load, so a document that cannot be run fails loudly instead of running as something else.

levelwhat is accepted
top levelheader, model, data, method
methodsites, reads, writes, intervened_models, featurizers, metrics, train, save

Inside that, it is narrower than the plan-shaped format on almost every axis: one mechanism (swap), one featurizer kind (subspace), one optimizer, one early-stop mode, two roles (base and counterfactual), one position form (an integer index), a site at one layer with no heads and no units, and one flat save list rather than a save per step. There are no steps: the order of execution is implied, so a document with a fit is fit, then observe, then weights.

It has no schema, and its refusal of an unknown key is written out by hand at each level rather than falling out of the type. Those are the two things pydantic does for the plan-shaped format, and the reason that format exists. validate says which reader took a document:

$ uv run causalab-mini validate documents/minimal_cpu.json
ok: documents/minimal_cpu.json is a valid protocol document

The nine documents at the top of documents/ are in this format; documents/v2/ and documents/real/ are plan-shaped. Write new documents in the plan-shaped one.

What is not a document field

A document is the experiment. Where it runs, how much of it runs at once and where the results land are the run's, and are flags:

flagdefaultwhat it decides
--enginennterpnnterp, hooks, or ndif — the same document with no local weights
--device-mapautowhere the weights sit. Ignored by ndif, whose weights are the server's
--batch-sizeevery row at oncerows per model call; bounds memory, moves only the last bit
--data-rootdocuments/datawhat a dataset ref is relative to
--outoutthe directory the save tree is written under

None of them enters the digest, which is the point: the same document scored locally and on NDIF is the same experiment, and the numbers are comparable because nothing about the run is in its identity. What is recorded is the run: run.json, written beside the results, carries the engine, whether it was remote, the batch size, the library versions, a digest of this package and the dtype the model was actually served in.
