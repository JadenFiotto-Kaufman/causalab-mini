Standardization

nnterp names and reaches a tensor; mini decides what may be done there.

causalab_mini/address.py is the only file in the project that knows anything about a model's internals, and most of what it knows it asks nnterp for. The split is one sentence: which module or operation is "the mid-stream of layer 3" on this architecture is nnterp's question, and whether a document may name that place, and what happens there is mini's.

The mechanism on the nnterp side is one table of Address rows. A row is pure data: a module path in standardized names, which side of it, any .source operations to descend through, where the tensor sits in the value there, where it sits in the forward pass, and why a family has none. A family that differs differs by a row, not by a branch of code.

At a glance

One name, two families that spell the block and its children nothing alike — tiny Llama's first block is model.model.layers.0, tiny GPT-2's is model.transformer.h.0:

from nnterp import StandardizedTransformer

for key in ["hf-internal-testing/tiny-random-LlamaForCausalLM",
            "hf-internal-testing/tiny-random-gpt2"]:
    model = StandardizedTransformer(key, device_map="cpu")
    row = model.internals["layers_mid"].address
    print(f"{key:48} {model.block_structure:10} {row.module!r} {row.io.value}")

prints:

hf-internal-testing/tiny-random-LlamaForCausalLM pre_norm   'post_attention_layernorm' input
hf-internal-testing/tiny-random-gpt2             pre_norm   'ln_2' input

Mini's block_mid is that row's name and nothing else, so the address mini compiles is equal on both checkpoints — same component, same layer, same resolved operation. That equality is asserted for every one of mini's components in tests/test_components.py::test_one_address_serves_both_families. Mini has no family axis and no family column; the axis is absorbed by the dependency.

Where the line is

What nnterp answers, for every place it addresses:

  • which child module this family spells the place with, and which side of it — or which operation inside whose forward;
  • whether the place exists at all on this architecture, and on this layer, with the reason when it does not;
  • where the tensor sits inside the value there;
  • where the place sits in the forward pass;
  • every width and head count — hidden_size, intermediate_size, head_dim, qk_head_dim, num_kv_heads.

What mini keeps beside the accessor's name is policy: which axis of the tensor the sequence runs along, whether it is per head and per which heads (q or kv, which differ under grouped-query attention), whether its last axis is the keys of a padded batch rather than a feature width, which model attribute publishes its width, whether a write there is refused, and the four interiors nnterp does not address.

why the line is there

The families disagree about where a block's places are, and the disagreement is invisible from a module name. Gemma-2/3 and OLMo-2 normalize a sublayer's output before adding it, so the attention module's raw output is not the contribution — on google/gemma-2-2b its norm is 17x smaller than the stream it would be taken as part of (recorded in nnterp's changelog). GPT-NeoX's second norm exists and normalizes the block input. BLOOM adds the residual inside its sublayers. The o_proj input is heads · head_dim wide, not hidden_size, on Qwen3 and Gemma.

FINDINGS.md §23 records the exploratory pass over 24 families that found these. Each one carried on mini's side is a second family table beside nnterp's, which is the reason there is one.

What an Address row is

fieldwhat it answersdefault

per_layer One per layer, reached as accessor[i], or one per model, reached as accessor(). True

Every row of the table becomes an attribute of the model — model.layers_output[i], model.lm_head_output() — and a member of model.internals, which is the rows by name in forward order. Adding a place is adding a row and nothing else. A row whose name the model already uses is refused at load with a message saying to rename it, rather than replacing the attribute.

model.logits and model.token_embeddings are the two exceptions, and they are spellings rather than exceptions to the table: each stays the tensor property it is and reads its row (logits and embeddings_output), so there is still one answer per place. Locations has the component table and why logits and lm_head are not the same tensor on every family.

A family that differs is one row

FAMILY_ADDRESSES is a list of (model class or predicate, rows); the defaults are applied, then every entry that matches, then the user's RenameConfig. Later entries win. Each row is replace() on the default one, so an override states only what differs.

familywhat its rows say
OPTmlps, mlps_input, mlps_output are unavailable: the block has no MLP module, its feed-forward layers are its own fc1 / fc2.
Gemma-2, Gemma-3, OLMo-2attentions_output is post_attention_layernorm and mlps_output is post_feedforward_layernorm: these families normalize a sublayer's output before adding it, so the post-norm's output is the tensor added to the stream.
BLOOMattentions_output is self_attn.dense, mlps_output is mlp.dense_4h_to_h, and the pattern is a different .source operation.
BLOOM with slow_but_exact Both contributions are unavailable: these checkpoints compute the output projections with F.linear, so no module carries the sublayer's additive contribution.
MPTmlps_output is mlp.down_proj; the pattern is a bare nn_functional_dropout_0.
DBRXSix rows. Its norm_1 is inside what nnterp calls self_attn, so it comes after that container's input rather than before it — an order override, not only a path one.
Falcon, Falcon with alibi, GPT-J The pattern's operation only: these forwards reach the softmax by a different route.
GPT-OSSOne tag, "sink": the softmax spans the keys plus a sink and the sink is dropped, so the pattern sums to less than one.

A place on a child nnterp does not rename

nnterp standardizes the block, the mixer and the MLP. It does not rename their children, and families spell them differently: input_layernorm or ln_1, o_proj or c_proj or dense or out_proj, act_fn or act or gelu_impl. Which spelling a model uses is a question the checkpoint can answer, so STRUCTURAL_ADDRESSES holds the candidates and structural_addresses reads the module tree: the row's {name} becomes the one candidate that exists.

If none exists, or several do, the place is unavailable with a reason naming the candidates it looked for, the children the layers actually have, and RenameConfig(addresses={…}) as the way to say which. Guessing by shape is exactly the silent failure this removes.

Six rows are resolved this way. On the two fixtures:

layers_mid and mlps_norm_output land on the same module and differ by side: the mid-stream is what the pre-MLP norm reads, and the norm's output is what the MLP reads.

Block structure, and why the tree alone is not enough

model.block_structure is how a block combines its two sublayers with the residual stream, read from the model's class and config: pre_norm, sandwich_norm (Gemma-2/3), post_norm (OLMo-2), parallel (GPT-NeoX, GPT-J, Falcon, Phi, StableLM-2) or residual_inside (BLOOM, MPT, DBRX). Each structural row's candidates are keyed by it, and a structure with no such place holds the reason instead of the candidates.

Keying by structure rather than by name is the whole point, because the same child name means different things on different blocks:

  • A sandwich-norm block spells the pre-MLP norm pre_feedforward_layernorm and also has a post_attention_layernorm — which there is the attention's post-norm. A candidate-existence rule would pick it and read a real tensor of the right shape from the wrong place.
  • A post-norm block has the children and not the places: attention reads the residual stream itself, and the norm comes after the sublayer.
  • A parallel block has no mid-stream at all, because attention and the MLP both read the block input — and on GPT-NeoX a second norm exists anyway, normalizing that input.

What holds the names to their meanings is that each place is defined by what it is of the block, as an identity over the tensors:

layers_mid       == layers_input + attentions_output
layers_output    == layers_mid   + mlps_output
mlps_norm_output == mlps_input

and, on a parallel block, layers_output == layers_input + attentions_output + mlps_output. A row that resolved to a plausible neighbour satisfies none of them.

Selection: where the tensor is inside the value

A place does not always hold the tensor directly. A module may return its output beside a cache; the model's own output is an object with a logits field. Address.select is where the tensor is inside that value, and it is a pair — get to read and put to write — because a write has to hand the place back its whole value with one part replaced, rebuilding tuples, named tuples, lists and mappings on the way out.

selectwhat it does
None The value untouched, tuple or not: what the place holds is what you get, and what you write is what it gets.
Index(*steps) Indices and keys walked in and rebuilt on the way out. Index(0, 1) is one step of each; a row may spell it as a bare 0 or (0, 1).
FirstIfTuple() The first element where the value is a tuple and the value itself where it is not — decided at each access, since the layers of one model need not agree.

Four rows of twenty carry one. Three are FirstIfTuple() — attentions_output, mlps_output, layers_output — and one is an Index: logits, which reads the logits field of the model's own output.

measured, not assumed

Those three are the places a module returns its tensor in a tuple on some families, over the 26 families of nnterp/tests/test_block_invariants.py. No other place in that sweep is ever a tuple. Deciding per access rather than per model is what lets a model whose layers return different structures be read in any order — and a row that points at a norm or a projection instead returns what that module returns, untouched.

Forward order

nnsight will not reach back to a value the model has already passed: reading layer 8 and then layer 2 in one trace raises, and a write has to go in above the read that observes it. So a place's rank in the forward pass is part of its row. internals.rank(name, layer) is (layer, order) for a per-layer place; a whole-model place gets (-1, order) where its order is negative and (num_layers, order) where it is not, which puts the embeddings below every layer and the final norm and head above.

Mini stamps that answer into the address rather than keeping a second numbering beside it — nnterp moves a place's order per family, and two numberings are how they drift apart with nothing saying so. The four interiors, which nnterp does not address, are mini's own numbers interleaved into nnterp's: 11, 12, 15 and 22, in the gaps nnterp leaves between its 10, 20, 25 and 30 inside the attention. The three nnterp rows mini's table does not name (attentions, attentions_input, mlps) are still addressable; see below.

How mini consumes it

locate(model, component, layer) is the whole of it. It asks model.internals[accessor] for the row, asks unavailable_on(layer) whether the place exists here, asks internals.rank where it sits, and writes the resolved child, the side and the rank into an Address that stays pure data — so it pickles, sorts, prints, and travels in a plan that an engine without nnterp's accessors can still walk.

In the trace, a boundary is one line each way:

model.internals[address.accessor][address.layer]            # read
model.internals[address.accessor][address.layer] = tensor   # write

Two things are cross-checked rather than trusted. locate compares mini's per_layer against nnterp's and refuses if they disagree, naming the table as mini's to fix; and a place the family or the layer lacks is refused at compile time with nnterp's own reason, rather than inside someone else's process. causalab-mini model is that, for every component at once:

What is still mini's

Four interiors: attention_query, attention_key, attention_scores, attention_z. The tensor never crosses a module boundary, so the address is a module plus one operation inside its forward, reached through nnsight's .source. The query and the key are positional arguments 1 and 2 of the attention interface call; attention_z is that call's return, element 0. nnterp's design document lists these among the things its internals layer does not address, along with per-head indexing and a tensor-layout descriptor — so the per-head slicing is mini's too, and a per-head tensor is handed on flat however the model holds it.

Mini names such an operation by its call site, not by its name, and find_op resolves the name against the loaded checkpoint. nnsight names an operation {callable}_{occurrence} and gives assignments the same namespace as calls, so this forward has both attention_interface_0 (the assignment that looks the implementation up) and attention_interface_1 (the call). A name match on attention_interface hits both and is refused with the forward's whole operation list; the needle "attention_interface(" is call-shaped and hits one.

why not a name

A binding's suffix does not survive the trip between families, and FINDINGS.md §1.11 records the measurement: query_states_0 is the query on tiny Llama and the cross-attention query on tiny GPT-2 — a branch that checkpoint never runs. An address spelled as the binding reads the right tensor on one family and a never-executed branch on the other, with no error. A call-op suffix counts calls of one symbol, and both forwards call the interface once, so both resolve to attention_interface_1 despite GPT-2's forward being much larger.

attention_scores is a step further in: the softmax's argument inside the function the interface call dispatches to. nnsight can only open that nested source inside a trace — which function the call dispatches to is a run-time fact — so the table holds the inner operation's name and the engine resolves it where the run runs. It exists only under eager attention, and that is checkable on the client, so locate refuses at compile time and says what to write: "attn_implementation": "eager" in the document's model block.

Positions are mini's too, for the same reason the components are nnterp's: Llama's tokenizer prepends a BOS and GPT-2's prepends nothing, so without a content frame {"index": 0} is <s> on one family and the first word on the other — one document addressing two different things, silently. See Positions.

Adding an architecture, or a place

An architecture nnterp has never seen is a RenameConfig: the names of its containers (attn_name, mlp_name, ln_final_name, lm_head_name, model_name, layers_name) and, where a place is somewhere else, an Address row for it. addresses={…} is the general form of the three narrower fields beside it: it replaces where an existing accessor reads, or adds one of your own.

from nnterp import StandardizedTransformer
from nnterp.rename_utils import Address, IOType, RenameConfig

config = RenameConfig(addresses={
    "attentions_gate": Address("self_attn.q_proj", IOType.OUTPUT, order=15),
})
model = StandardizedTransformer("hf-internal-testing/tiny-random-LlamaForCausalLM",
                                device_map="cpu", rename_config=config)
print("attentions_gate" in model.internals)
print(repr(model.internals["attentions_gate"]))
True
<attentions_gate: self_attn.q_proj.output, per layer>

Mini's table is a floor, not a fence. A component name mini has never heard of but model.internals has is addressable, because a document should be able to name what a user added. The same row, through mini, resolves at layer 1 to module='self_attn.q_proj', io='output', rank=(1, 15). Mini claims nothing else about such a place: no width, so a featurizer there is refused rather than sized wrongly, it is not per head, and it is a module boundary.

When transformers moves

A .source row names operations the way nnsight names them, which is a fact about the installed transformers version and not about the architecture. An upgrade that moves a call, renames a local, or routes a family through the shared attention interface invalidates a row. Two suites stand against it:

suitewhat it asserts
nnterp/tests/test_block_invariants.py Over 26 families: the published block structure, what the family lacks known before any trace, every available accessor reading a tensor on every layer, the residual identities, the published sizes checked against the tensors and modules rather than the config, and a write at each new accessor landing.
nnterp/tests/test_source_ops.py The same 26 families loaded with the attention probabilities enabled, so every operation row has to resolve. The tensor is then checked to be a pattern — non-negative, [batch, heads, queries, keys], summing to one (to less than one where the row is tagged "sink"), and equal to a manual softmax of the scores where the forward makes them reachable.

A row that drifted onto the scores, the values or the post-mix output passes a shape check and fails these. And when a row does break, the error names the row, the module, the transformers version, the model class and every operation that does exist at that level of the source:

Remote

A request carries nothing of nnterp. The package is not registered for by-value serialization, so an NDIF server runs its own installed copy and must have it at the same version as the client. The same flag keeps the checkpoint off the client: remote=True sets allow_dispatch=False, every load-time check runs with scan() on the meta model, and no request is sent during construction.

Mini is on the other side of that line and says so: it calls nnsight.register("causalab_mini") before a remote run, because its own package is not installed on an NDIF server and the functions a traced block calls have to ship by value. What ships is mini; what is already there is nnterp. See Remote & NDIF.
