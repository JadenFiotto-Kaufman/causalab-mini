Use case

Attention pattern

Patching the attention pattern: does where a head looks carry the answer?

Head patching says one head of Llama-3.2-1B carries "today" to the last token: L12 H28. A head does two things there — it decides where to look, and it moves what it finds. A patch of the head's result changes both at once, so it cannot tell you which.

The attention pattern is the first half on its own. Swap it from the counterfactual prompt and the head looks where it would have looked on that prompt, while the values it mixes are still this prompt's. If "today" travels by the head's aim, the answer moves. This page runs that, per head of layer 12, on the real model.

At a glance #

Nothing moves. All 32 heads of layer 12, mean logit difference over the 42 pairs, counterfactual answer minus base answer:

headlogit difference, measured from −2.409
L12 H28 −2.396
L12 H18 −2.398
median head −2.403
L12 H15 −2.409

The bars are measured from −2.409, the lowest of the 32, because measured from zero all 32 are the same bar. The whole spread across every head of the layer is 0.013 logits, and the interchange accuracy is 0.00 on every head and every row. The mover head's pattern is not what makes it the mover head.

Most of its length is the head sweep: 32 single-element lists, [[0], [1], … [31]], one point per head. Apart from that and the model block, it is the layer sweep's document with a different site — read from the unmodified model on the counterfactual prompt, swap into the base run, score the head's logits against the two answers.

Two things this document says that others do not #

"attn_implementation": "eager" #

It sits in the model block, beside the checkpoint and the revision, because it is part of the experiment and not of the run. Two reasons it belongs there rather than on a command line:

  • eager is the only implementation under which attention_probs and attention_scores exist. sdpa and flash attention never materialize the pattern as a tensor — the whole point of them is that they do not — so there is nothing to address.
  • The implementations differ in the last bits. A result produced under eager is not bitwise a result produced under sdpa, and a document that did not record which one ran would not be reproducible.

Leave it out and the address does not resolve. model asks the question without running anything:

The pattern is over keys #

attention_probs is (batch, head, query, key). The site's heads picks the head axis; pos cuts the query axis, so -1 is "what this head attends to when producing the last token"; and the key axis is left whole, because a pattern is a distribution over keys and half of one is not a pattern.

key j lands on key j

A swapped-in pattern is a vector of weights over the padded batch's key positions, and key j of the operand lands on key j here. That is only the same token if the two prompts are laid out identically: the same padded width and, row by row, the same number of real tokens. Otherwise attention mass meant for one word lands on another, or on a pad, with every shape correct and nothing to notice.

Both attention masks are in hand before any forward, so this is refused at compile time rather than discovered later — or not discovered:

$ uv run causalab-mini explain pattern_on_unaligned_rows.json
…
causalab_mini.plan.plan.PlanError: write 'look_there' swaps in the attention pattern 'their_pattern', read from prompts laid out differently: rows [0, 2] have [9, 11] tokens there and [11, 9] here. A pattern is over keys, so the two prompts must tokenize to the same length, row by row

That is why documents/v2/ has a weekdays_aligned corpus at all: on the tiny tokenizer Thursday is three tokens and Friday is one, so only some pairs line up, and the aligned corpus is the six that do. On Llama-3.2-1B every weekday name is one token, so the whole 42-pair corpus is aligned and the real document needs no subset.

features=[0]/32 is the head selection: head 0 of the 32 this layer has. A site with heads narrows the tensor to those heads, and it is the same field whether the component is a pattern, a query or a head's pre-projection result.

For scale, the layer sweep's table has both ends of this ruler. A patch at the last token before layer 12 does nothing and reads −2.40; the same patch at layer 14 or 15 moves every row and reads +2.3 to +2.4. The pattern swap moves the number by about a quarter of one percent of the distance between them.

What the head does instead #

The contrast is the point. The same head, the same position, the same corpus, with the swap moved from its pattern to its result:

what is swappedcomponentL12 H28median headIIA at H28
where the head looksattention_probs−2.396−2.4030.00
what the head movesattention_premix+0.054−2.4030.50

The second row is documents/real/weekdays_head_patching.json — 96 points, every head of layers 10, 11 and 12 — run the same way, 8 m 09 s on CPU. One head of the 96 stands out, and it is this one: swapping its result moves the mean logit difference from −2.403 to +0.054 and flips half the 42 answers. The same head's pattern, from the same prompts, moves nothing. documents/real/README.md records +0.05 and "flips half the answers" from the A100 run.

So L12 H28 attends the same way whatever the day is. Its aim is not a function of the answer, and importing the counterfactual's aim imports nothing. What it carries is in the values it mixes — the head is a pipe whose position is fixed and whose contents are the fact.

what a null result here does not say

"The pattern carries nothing" is a claim about this task, this position and this layer. The prompts differ in exactly one word at a fixed offset, so the two patterns being interchangeable is unsurprising in hindsight — a task whose counterfactual moves a word, or changes the number of items to attend to, would not look like this.

It is also a claim about a swap at the last query position only. A head whose pattern matters earlier in the sequence would not show up: nothing was swapped at any other query.

And a pattern swap is not a knockout. Zeroing a head's pattern asks a different question — whether the head contributes at all — and documents/v2/attention_knockout.json is that document, with "operand": 0.0 in place of a read.
